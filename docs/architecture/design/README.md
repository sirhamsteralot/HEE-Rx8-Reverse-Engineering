# Firmware design document — 60E15120_N3J1E (RX-8 PCM, SH7055 / SH-2E)

Related: [emulated OBD-II/UDS path design](../emulated-obd.md) — how the emulator
exposes the PCM's diagnostic interface as if it was in a real car.

How the firmware is built up and what calls what, from the
canonical export (`decompiled/`), the reviewed alias tables, and the review
folders (`hardware/`, `cross_ecu/`, `source_review/`, `math_units/`,
`lookup_family/`, `readability/`). Statistics are regenerated by
`scripts/design_graph_stats.py` into `graph_stats.json`; cross-checks are in
`validation.json`. The knock-control and loop-mode labeling is section 5.7
(see `reviews/knock_control/`).

This is a **static, direct-call view**. Names marked `ref_` are inherited from
the reference ROM (60E0FC00) project and remain hypotheses; `FUN_` names are
address-based; reviewed aliases carry their own confidence in the review
folders. Nothing here is validated by execution.

## 1. Target and memory map

Renesas SH7055 (SH-2E, SH-2 + FPU), big-endian, 512 KiB flash, 32 KiB RAM.

| Region | Range | Role |
|---|---|---|
| Vectors | 0x00000000–0x000003ff | Reset/exception/timer vector table |
| Code | 0x00000040–0x00068e3e | 3,355 identified functions (vector slots 0x0–0x3ff also hold small trampolines) |
| Descriptors + calibration | 0x0006c000–0x0007ffff | Table descriptors, lookup data, strings; calibration ID `N3ZHE` at 0x6c046 |
| RAM | 0xffff6000–0xffffdfff | Working data; task stacks end at 0xffff7498 |
| Volatile I/O | 0xffffe000–0xffffffff | SH7055 peripheral registers |

Corpus-wide flash/memory layout (all 11 ROMs, with diagrams and the
per-ROM differences): [flash-memory-layout.md](../flash-memory-layout.md).

## 2. Entry points

The firmware has four entry mechanisms, all visible in the export:

1. **Reset and exceptions** (vectors at 0x0–0x34): power-on/manual reset →
   0x8b8 `ref_Manual_Reset`; all exception vectors → 0x8b4 `Illegal_instr`
   (a terminal halt loop — most of the 15 "infinite loop block" decompiler
   warnings are these intentional stops).
2. **Periodic timer interrupts**: ATU-II channel 10B compare **CMI10B**
   (IVT offset 0x2c8 at VBR 0x7fc50 → trampoline 0x2ec0 → handler **0x5b3c**)
   is the crank-angle-synchronous OS tick (see §4). Note: the label
   `ref_INT_ATU101_IMI10AG`/`vector_INT_ATU101_CMI10B` at 0x803e is the **default
   (VBR=0) vector-table entry** (ROM slot 0x2c8), inactive once VBR=0x7fc50 is set;
   the live path is
   0x5b3c → 0x75f4 → 0x77f0 → 0x7c68 → `ref_getCrankAngle` 0x7fcc
   (see [the OS scheduling deep dive](../../investigations/60E15120_N3J1E/os_scheduling_deep_dive_report.md)).
   ATU102 IMI10AG (vector 0x2d0 → 0x9fc `INT_ATU102_IMI10AG`, 210 bytes, also
   invoked from the boot path at 0x170).
3. **Scheduled tasks**: a 19-record task table at **0x4990–0x4ab7**
   (16-byte records: `{param, stack-ctx, entry, mask}`; context blocks
   0xffff7408–0xffff7498). Every record's entry is a function in the index.
   This table is the main run-time entry mechanism. Base
   0x4990 (19 records), proven by the pool 0x37b0 = 0x4990 load and the
   stride in `os_switch_to_task` 0x375c.
4. **Diagnostic dispatch**: 99 twelve-byte records at **0x5f10c–0x5f5af**
   (`{identifier, availability_mask, response_length, handler}`); searched and
   dispatched by `diag22_find_and_dispatch_identifier` (0x5774c). All 99 records
   are labeled (see [the UDS/Mode-22 dispatch report](../../investigations/60E15120_N3J1E/uds_mode22_dispatch_report.md));
   the UDS service table (29 records) lives at 0x5eb40 with router 0x68dac.

## 3. Boot flow

```
vector 0x0/0x8 -> 0x8b8 ref_Manual_Reset
  -> 0x4e0 ref_resetHandler_
       -> 0x31c service_wdt_overflow_and_toggle_pb15   (external watchdog heartbeat idiom)
       -> 0x572 ref_resetWatchdog_, 0x5b0 ref_checkWatchdogTimer_OVRCOUNT
       -> 0x170 FUN_00000170  (ATU timer setup: 0x9c0, 0x9de, 0x9fc INT_ATU102)
       -> 0x3d4, 0x41c, ... (early init; 22 functions reachable from reset by direct edges)
  -> 0x8cc, 0x8f6 (small init stubs)
```

`ref_mainInit__` (0x61a8) initializes the subsystems — `ref_setRegisters`
(0x4d2e), `ref_ignitionDwellOutputInit` (0x8f2a), `ref_misfireDetectInit_`
(0xab8a), `ref_knockFunctionInit` (0xc14c), plus `FUN_0001102a` (85 callees,
the largest init fan-out). **No caller for 0x61a8 exists in the call graph,
the disassembly, or as a ROM32 pointer** — its entry mechanism is unresolved;
the name is inherited from the reference project.

## 4. Runtime architecture: scheduler and tasks

The scheduler/OS, IVT and CAN/UDS transport are labeled from
emulator execution — see `docs/investigations/60E15120_N3J1E/os_scheduler_can_ivt_report.md`
(os_init 0x3e10, os_dispatch 0x3c2a, os_switch_to_task 0x375c, wake 0x3db0,
IVT at VBR 0x7fc50, CAN RX interrupt IVT 0x378). The full scheduling model
(task loops, message queues, crank-angle-synchronous tick, timers) is documented
in [the OS scheduling deep dive](../../investigations/60E15120_N3J1E/os_scheduling_deep_dive_report.md);
the diagram below reflects it.

```
CMI10B tick (IVT 0x2c8 -> 0x5b3c, per crank sector: OCR10B = tbl 0xd76d[sector],
  sector 0xffff9f95 via tbl 0xd76c) -> 0x75f4 -> 0x77f0 -> 0x7c68 -> 0x7fcc (rpm)
  -> on crank edge 0xcf96 -> 0xa156 -> ref_osTaskScheduler 0x9630(1,9,..)
CAN RX (IVT 0x378 -> 0x5e78 -> 0x9c86) -> 0x9630(1,12,..) target -1 -> 0x11d88 inline
other live vectors: 6x ATU ch8 injector compares (0x59a4-0x59ea), knock ADC 0x5a4c,
  ch3/ch9, 3x ADC EOC, CMCSR1, IRQ flags; 98 of 117 vectors = fatal trap 0x5348
        |
  ref_osTaskScheduler (0x9630)  group descriptor tables via ptr table 0xd87c
    -> target -1: call handler inline (ISR context)
    -> else FUN_00005f1c (0x5f1c): post 5-word {handler,args} message into a ring
       queue (ROM records 0xd74c+8i {buf, task id, depth}; bufs 0xffff9310/93d8/
       94a0/96f8; state 0xffff9304+3i {wr, rd, count}), via FUN_00003854 (credit
       byte ctx[3] -= 1) -> FUN_000039ba: ready ring (ctrl+0x24 = 0xffff74a0) +
       class bitmap 0xffff7668; preempt: class > ctrl[0] (unsigned) -> ctrl+6
  ISR exit epilogue 0x3280: if a task is scheduled -> context switch 0x32f4
    -> os_switch_to_task 0x375c (fresh: rte via 0x3848; resume: jump table 0x4b34)
task table 0x4990 (19 x 16-byte {param, stack-ctx, entry, mask}) --dispatch via-->
  os_dispatch 0x3c2a -> 0x3c68 -> 0x375c; task ends: ref_taskEndRoutine_ 0x3d58
  -> os_dispatch again; nothing ready -> idle spin 0x3dac (bra self)
consumer tasks 0x969e/0x96be/0x96de/0x96fe dequeue one message (os_queue_dequeue_record
  0x6010) and call its handler; task[0] 0x62a0 is the never-yielding background loop
```

Scheduling requests also arrive through `ref_putTaskInSchedule_FuelArrayStuff`
(0xa10e) and the post wrappers at 0xa0de–0xa22c (0x18-byte spacing, fixed
group/idx immediates) plus ~20 larger callers of `ref_osTaskScheduler`.

Record 18 at ROM **0x4ab0** (last table entry; terminator at 0x4ac0) is
{param 0x04000100, ctx 0xffff7498, entry **0x64e8**, mask 0x02000000}.
0x64e8 is a thin wrapper (`FUN_00011534` + `ref_taskEndRoutine_`) leading to
the 29-call slow/background task 0x11534 (torque params, diag-mode timer,
immo counter, …); see
[the OS scheduling deep dive](../../investigations/60E15120_N3J1E/os_scheduling_deep_dive_report.md) §4.

The mask byte (0x01/0x02/0x0a/0x1e/0x64) is the task's **weight/credit**
byte, copied to ctx[3] at init (0x3ec0), decremented per posted message
(0x3854) and restored at taskEnd (0x3d58); the param byte 2 is the task's
**priority class** (used by 0x39ba for the ready bitmap and preemption).
Task periods are not fixed wall-clock values — the tick is crank-angle
synchronous and timers are per-task counters (deep dive §1/§5).

### 5.7 Knock control and loop mode

Labeled and traced in `reviews/knock_control/README.md`. The
chain is loop-mode independent: **knock control applies in open loop as well as
closed loop** — none of its functions read the loop-mode flags; its gates are
engine conditions only (run time, coolant, load, RPM, sensor health,
timing-not-already-retarded).

```

  -> ref_functionDrivingTiming (0xc338)
       -> 0xc8dc knock_sensor_sci_command   external knock amp over SCI0:
       -> 0xc276 knock_reference_adc_read    per-rotor threshold command out,
       -> 0xc3ce knock_voltage_sample        filtered level in (200-2000 RPM window)
  -> 0xc7ba ref_setupCoilOutputs            coil timing, thresholds a37e/a37c

  -> engine_speed_rpm_raw_ffff9f80 (1.2e8 / crank period sum; 0x803e is an
  uncalled duplicate of this math)

               0x33970 knock_attack_condition  raw thresholds -> a37e/a37c, c05c
```

Loop-mode decision (polarity corrected in this pass — 0xffffb12a/b12c are the
**open**-loop flag, 1 = open loop):

```
0x1f0c4 open_loop_request_condition   -> open_loop_request_ffffb12a (load/throttle thresholds)
0x1ee30 set_open_loop_flag            -> open_loop_active_ffffb12c = (b12a != 0)
0x1c13c closed_loop_enable_condition  -> closed_loop_allowed_ffffae1e (requires b12c==0),
                                          closed_loop_active_ffffae1f (lambda feedback aa80/aa81)
0x1ee4a open_loop_fueling_targets     -> open_loop_fuel_target_ffffb120 (0 in closed loop)
0x22144 candidate_evap_open_loop_condition -> b319 gated on open_loop_active_ffffb12c
```

What loop mode changes is the fueling around the knock correction (targets,
blend weights b11c/b118, not the knock correction itself). The loop-mode
handlers are `set_open_loop_flag` (0x1ee30) and
`reset_knock_state_on_mode_change` (0xc116).

## 8. What this view does not show

- **Indirect dispatch**: the computed jump at 0x37ac, the chained pointer
  tables at 0x420c/0x4218, the recovered shift dispatchers 0x43c8/0x44e0, the
  diagnostic dispatch table 0x5f10c and the task table 0x4990 are entry
  mechanisms invisible to direct call edges; reachability from them is
  under-approximated (3,157 functions are not reached from reset+timers+
  dispatch by direct edges alone — expected, since the scheduler reaches
  tasks only through the task table).
- **Decompiler caveats**: the interrupt-mask `ldc` side effect is invisible
  in raw C at 0x3920; register-derived ABIs remain imperfect in many bodies;
  154 functions carry categorized decompiler warnings
  (`decompiled/decompiler_issues.tsv`).
- **No execution evidence**: scheduling order, interrupt load, stack depth and
  worst-case timing are unmeasured (see `reviews/reset_at_10000_rpm.md` for
  the open reset investigation).
