# Axis search and interpolation family

This incremental pass reconstructs 18 related routines in the canonical C, starting from the poorly named axis helpers and their callers/callees. The previous export is preserved in `backups/pre_lookup_family.zip`. The ROM and saved Ghidra database are unchanged.

The crucial discovery is that **0x2624 returns an index and a fraction**, not just an index. Its R0 output selects the lower breakpoint and FR0 carries interpolation position. `Rx8AxisPosition` expresses those two register outputs in analysis C; it is not a claim about the compiler's original struct-return convention.

0x2658 performs two searches, saving X and Y indices/fractions in R2/R3 and FR0/FR1. Both calls matter. It is now `rx8_find_xy_axis_positions`. Lookup wrappers now pass explicit inputs to searches and pass the results to interpolation, replacing the previous uninitialized `in_fr*` artifacts in this family.

The two formerly identical `ref_interpolate_floatTable` names now distinguish one-dimensional interpolation from interpolation across two axes. Related signed/unsigned byte, signed/unsigned word, and float variants use consistent names. The ROM dispatch arrays at 0x2098 and 0x210c establish type-byte offsets 0, 4, 8, 12 and 16 for those variants. Both dispatch arrays were checked directly against the input ROM.

## Semantics deliberately retained

- The upper-end test branches on NOT greater-than, including unordered comparisons. A NaN input therefore takes the last-index/zero-fraction path; the tempting `axis[last] <= value` rewrite would differ.
- Values below the first breakpoint return index zero and fraction zero. Interior searches also calculate the fraction, including the original subtraction/division order.
- No empty-axis guard was inserted: callers must supply valid nonempty axes. Malformed pointers/counts are not assigned safe invented behavior.
- Zero fraction avoids reading the next element or next row. Endpoint access depends on this branch.
- Two-axis row offsets retain the SH signed-low-16-bit multiplication, rather than becoming unrestricted host pointer arithmetic.
- Float multiply-accumulate and FTRC are explicit `rx8_sh_*_model` operations. Their declarations intentionally leave target rounding, exception and exceptional-input behavior unresolved. The host test supplies test-only implementations.
- Unknown type-byte dispatch remains an explicitly unresolved operation. No fabricated zero, NaN or error return was substituted.

These are readable models of normal, valid-table execution. They are not a fully linked firmware replacement or an instruction-accurate emulator for malformed addresses, pointer wrap on 64-bit hosts, signaling NaNs or target exception settings. External callers with unrecovered lookup arguments remain listed in the earlier readability audit; this pass fixes the family's internal dataflow, not every caller in the ROM.

## Records and checks

[analysis_record.json](analysis_record.json) and [analysis_record.md](analysis_record.md) provide the requested old name, new name, confidence, reason, evidence and remaining uncertainty for each function. [remaining_inventory.json](remaining_inventory.json) retains the broad inventory of autogenerated names or implicit-register references for later clusters; it is not a claim those functions are all understood.

The canonical file, individual bodies, index, symbols and family call-graph edges were synchronized. All 3,355 individual bodies match the combined file, and existing ROM/instruction checks pass. Host tests cover 401 axis samples, NaN endpoint behavior, a single-element axis and five interpolation storage types. The sanitizer build was unavailable because the linker could not locate its ASan runtime; the ordinary strict-warning host build and tests passed.

To reproduce after prior cleanup passes: run `scripts/refine_lookup_family.py`. The supplied type header contains the explicit carrier types and helper declarations. To run the isolated host tests:

```sh
cc -std=c11 -Wall -Wextra -Werror -ffp-contract=off lookup_family/test_lookup_family.c -lm -o /tmp/rx8_lookup_test
/tmp/rx8_lookup_test
```

No changes to historical provenance comments are intended to erase the original reference name; current names are recorded alongside them.
