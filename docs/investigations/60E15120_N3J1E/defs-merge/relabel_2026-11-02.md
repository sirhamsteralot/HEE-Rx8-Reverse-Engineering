## 1a. Plain-language summary

The tuning definitions are the files RomRaider/VersaTuner use to show the PCM's adjustable
tables. Until now many were named "Table 2D - 3" or carried community guesses ("???"), and
about a hundred tables that exist in the ROM had no editor entry at all. This pass renames
the tables we actually reverse-engineered (fueling, ignition, knock, load, …) to what they
do, sorts them into the matching category groups (Fuel Injection, Knock Control, Ignition
Leading/Trailing, …), adds the missing tables with their real addresses, and stamps every
touched entry with a dated note saying where the name comes from. Nothing about the actual
calibration data changed: no address, axis, scaling or cell value was modified — only names,
groups and descriptions, plus whole-table additions for descriptors that had no entry.

## 2. Mechanics (what "label / update / group" concretely changed)

- **Label**: `name=` of the table entry. Renamed entries are made self-contained (type,
  storagetype, endian, sizes, scaling and axis definitions copied from the base-chain
  template of the same old name) so RomRaider's name-based inheritance keeps working; the
  prior name is kept in the `<description>` ("Prior editor name: …").
- **Update**: dated `<description>` addendum `[RE relabel 2026-11-02]` with descriptor
  address, semantics/units note, evidence, source report and confidence; the pre-existing
  2026-09-18 description is preserved above it. Added tables get full geometry from the ROM
  descriptor bytes (`data/maps/<rom>/tables/*.json` + scaled mult/offset from the descriptor)
  and the name `Table 2D/3D - 0x<desc> (unlabeled)` under category `Unknown 2D/3D` when no
  label exists.
- **Group**: `category=` set to the subsystem category (existing RX8Defs category names:
  Fuel Injection, Fuel Injection - Open Loop, Fuel Target (Closed Loop), Ignition Leading /
  Trailing / Timing, Knock Control, Engine Load, Idle Control, Sensors, …). RomRaider groups
  the table tree by this attribute.
- **Cross-ROM provenance**: non-reference ROMs record "cross-ROM structural match to
  60E15120_N3J1E descriptor 0x…; this ROM descriptor 0x…" in the description — structural
  match, not cell equality, per the label ladder.

## 3. Invariants verified

- **No pre-existing table changed** storageaddress, axis addresses, scaling, type or sizes —
  asserted by `tests/test_defs_relabel.py` (signature comparison old vs new for every
  per-ROM def and the merged def) and by the splice construction for the merged file.
- Every marked table's `storageaddress` equals the `data_addr` of its descriptor in
  `data/maps/<rom>/index.tsv` (address traceability, AGENTS.md rule 5).
- No new duplicate table names introduced (pre-existing upstream duplicates recorded, e.g.
  60E0FB00 "Table 2D - 85 ").
- Generator is idempotent (re-run produces byte-identical per-ROM defs + coverage.json).
- `python -m pytest tests/` — 78/78 pass, including the 4 new
  [`tests/test_defs_relabel.py`](../../../../tests/test_defs_relabel.py) and the pre-existing
  `test_extract_scalars.py::test_per_rom_defs_expose_scalars` (literal-pool scalar entries
  intact).

## 4. Known limits / not done

- **60E32000_N3M5E / 60E32000_N3N5EB per-ROM defs got no relabel**: the upstream `60E32000`
  block's storageaddresses join neither variant's `data/maps` extraction (join rate 0.0 —
  the upstream block was built for a different layout), so the pass skips them and records
  `skipped` in `coverage.json`. Fixing those defs' addresses is a separate work item.
- Labels propagate cross-ROM by **structure**, not by cell values; 39+ ROMs' tables with
  calibration diffs still match when the shape is unique. Tables whose shape is ambiguous
  and whose cells differ stay unlabeled (conservative, per the label ladder).
- `candidate_` labels keep their `(candidate)` suffix in the editor name; they must not be
  treated as verified (ROADMAP D6).
- ECUFlash defs remain upstream-only for 60E0G500 (documented gap in
  [`data/definitions/README.md`](../../../../data/definitions/README.md)).
- No RomRaider GUI load was performed; validation is XML-structural + invariant tests, not a
  GUI render.
