# Fuel pump control — review notes

Method, in order:

1. Enumerated all GPIO output sites: direct `P?DR_W` stores in the decompiled
   export (121 accesses), all `ref_setRegister_REG_BIT_VAL` (0x4bbc) call sites
   with constant reg/mask in the per-function files, and a raw-disassembly scan
   of every `jsr`/`bsr` whose r4-r7 hold a `0xfffff7xx` (or low-half `0xf7xx`)
   pool value. Result: the only dynamically driven, previously unlabeled output
   bits are PD7/PE0 (`0x3a0ec`), PE1/PE2 (`0x2f8ce`/`0x2f890`) and the PD4 PWM
   (catalyst-temp tables — purge-class, not a relay).
2. SH7055F package pins from `docs/references/Sh7055h.pdf` Table 1.3: PE0=7,
   PE1=8, PE2=9, PJ7=183, PD7=256, PD5=254, PB2=147.
3. Harness terminals still needing drivers (pinout v3): 4C DBW relay, 4M fuel
   pump speed, 5A starter, 5P/5L fuel pump relay, 5AA A/C relay.
4. Caller inventory by whole-ROM literal-pool scan, for each producer of the
   chain: `0x2f948` ← `FUN_0001102a` (pool `0x11308`, `jsr` at `0x11136`), and
   `FUN_0001102a` itself has exactly one reference — the init pool `0x628c`
   (`jsr` at `0x61e4`), so the prime runs once at start-up; `0x2f95c` ← the
   fueling-task worker `0x117ac` (pool `0x11a08`); `0x2f98c` ← `0x11b80` (pool
   `0x11d20`). Reader/writer sets per cell come from the same scan
   (`0xffffbdd8`: written `0x2fbf0`/`0x2fc00`, read `0x2f890`/`0x2f8ce`;
   `0xffffbdbc`: written `0x2fb20`, read `0x2f8ce`/`0x2aa46`/`0x49308`;
   `0xffffbdd5`, `0xffffbdd4`: `0x2fb20` only; `0xffffbdda`: `0x2fc00` only;
   `0xffffbddc`: `0x2fbf8`/`0x2fc00`/`0x2fcac`).
5. Dynamic discrimination in the SH-2E emulator (harness calls of the flag
   producers + output drives):
   - `0x2f890` sets PE2 from `0xffffbdd8` alone; `0x2f8ce` sets PE2 through the
     `0x5c204` gate and PE1 from `0xffffbdbc`; `0x2fc00` produces
     `0xffffbdd8` from `0xffffaa68` and the counters (key-on → 1, key-off → 0).
     PE2 is therefore the fuel pump relay candidate (5P/5L).
   - PE1 is the fuel pump speed control candidate (4M). Its request is the
     `0x2fb20` combination of the 3.5-hysteresis demand term, the
     injectors-off/key-on term and the (inert here) hold-counter term; the
     emulator runs do not drive a demand scenario, so this cell is exercised
     only through its producer's inputs.
   - PD7 high only while cranking (`0xffffd15c` from `0x532d0`: vspeed≈0,
     cranking `0xffffaa62`, engine_running `0xffffa428`, E2-shadow
     `0xffff86e8` < 0xea; chain `0x4ed3c`→`0x4ef86`→`0x3a0ec`) → starter relay
     (5A candidate). PE0 (`0xffffcfb7` inverted) mostly high → DBW relay
     (4C candidate).
   - PJ7 follows `0xffffbd68` from `ref_calculateACClutchOn__` `0x2e89c` → A/C
     relay (5AA). Corrects the earlier "fuel-pump candidate" note.
6. Inertia switch: no PCM input pin exists for it in the pinout; it sits in the
   fuel pump feed circuit hardware-side. Not a firmware condition.
7. Calibration-gated paths: `ROM[0x775bd]` (0x2fb20's third term) is 0x01 and
   `ROM[0x775bc]` (0x2f9fc's tail block) is 0x00 in this bin, so those two
   branches never execute here; both are recorded in the report §4.6 instead of
   being described as live behavior.
